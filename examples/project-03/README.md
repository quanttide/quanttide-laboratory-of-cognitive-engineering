# 项目三：图谱推理 vs 文本匹配对比实验

## 核心问题

对于一段新输入文本，**使用知识图谱的推理**比**纯文本关键词匹配**能否发现更多有价值的隐含关联？

## 验证方法

同一段输入 → 走两条技术路线 → 对比输出质量

```
输入文本
    ├─→ 方案A：纯文本分词 + 关键词匹配（不用图）
    └─→ 方案B：加载知识图谱 + BFS 遍历（用图）
                ↓
         对比：B 比 A 多发现了什么？
```

## 任务

### 3.1 构建知识图谱

从 YAML 加载并构建有向图。

**输入**：`../../../assets/refined/intent.yaml` + `../../../assets/refined/intent-relation.yaml`

**方法**：
1. 从 `intent.yaml` 提取 10 个节点（id, name, type, per_week intents）
2. 从 `intent-relation.yaml` 提取边（source, target, type, logic, weeks），包含 stable/periodic/situational 三类
3. 序列化为 `graph.json`（节点集合 + 边集合）

**输出**：`data/graph.json`

### 3.2 方案A：文本匹配（不用图）

基于分词和关键词表的纯文本分析。

**输入**：`data/graph.json`（只读取节点名和 per_week 中的 intent 表述作为关键词库）+ 测试文本

**算法**：
1. 对测试文本做分词
2. 用每个 Intent 簇的 per_week 表述作为关键词表，计算词重叠率作为匹配度
3. 匹配度 > 阈值则判定为该簇
4. 输出：匹配到的簇列表 + 关键词证据

**输出**：`scripts/approach_a.py`

### 3.3 方案B：图谱推理（用图）

基于知识图谱的图遍历推理。

**输入**：`data/graph.json`（完整的图和关系）+ 测试文本

**算法**：
1. **节点匹配**：用 3.2 的方法匹配到起始节点
2. **邻居发现**：从起始节点出发，列出所有直接邻居（支持/冲突/依赖）
3. **多跳路径**：BFS 遍历 2 跳，输出推理路径（node1 →edge→ node2 →edge→ node3）
4. **冲突检测**：检查匹配节点之间是否存在冲突边或间接冲突路径

**输出**：`scripts/approach_b.py`

### 3.4 对比执行

运行两个方案处理相同的 3 段测试输入，对比输出。

**测试输入**：准备 3 段不来自 `assets/raw/` 的文本
- T1：表面谈"加班太累"（期望：方案A 只匹配心理，方案B 推理出商业压力关联）
- T2：表面谈"招不到人"（期望：方案B 推理到团队→研发效率链）
- T3：表面谈"代码重构"（期望：方案B 推理到标准化/方法论）

**执行**：
```bash
python scripts/approach_a.py < test.txt  # 输出 JSON A
python scripts/approach_b.py < test.txt  # 输出 JSON B
```

**输出**：`outputs/results-a.json` + `outputs/results-b.json`

### 3.5 对比分析

逐项对比两个方案的输出。

| 对比维度 | 方案A（文本匹配） | 方案B（图谱推理） |
|---------|-----------------|-----------------|
| 匹配到的节点 | 列表 | 列表 |
| 推理出的关联 | 无（只能匹配） | 邻居 + 2跳路径 |
| 检测到的冲突 | 无 | 冲突边 + 间接冲突 |
| 推理可追溯性 | 无 | 可追溯到具体边+logic |

**输出**：`outputs/comparison.md`
- 每个测试输入的两方案输出并排对比
- 被方案B发现但方案A遗漏的关联标红
- 结论：图谱推理的增量价值评估
