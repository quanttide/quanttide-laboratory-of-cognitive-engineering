# 项目七：LLM 驱动的隐含关系推理

## 问题

当前图谱中 10 个意图簇关系稀疏——簇5仅连接 2 个邻居，簇10完全孤立。但人类可读的分析报告（`data/analysis/intent.md`、`intent-relation.md`）中包含大量隐含关系证据（事件触发、演化链、时序模式、冲突动态），这些从未被编码为图边。

**核心问题**：如何让所有簇相互关联起来？

## 方法：LLM 关系推理

用 DeepSeek 读取分析报告，为所有 45 个簇对推断隐含关系。

### 输入

- `data/analysis/intent.md`：五周意图演化全景
- `data/analysis/intent-relation.md`：意图关系分析
- `data/refined/intent.yaml`：10 个簇的原始数据

### 推理引擎

`exp_infer` 二进制执行以下步骤：

1. 读取分析报告 + 簇定义
2. 构建提示词，要求 LLM 推断每对簇之间的隐含关系
3. 对每对关系输出：类型、方向、推理依据、置信度
4. 生成完整关系矩阵 JSON

### 关系类型

| 类型 | 含义 | 示例 |
|:----|:-----|:-----|
| 支持 | A 的存在促进了 B | 心理可持续 → 研发执行 |
| 冲突 | A 与 B 之间存在内在矛盾 | 商业高压 ↔ 心理可持续 |
| 情感补给 | A 为 B 提供情绪能量 | 创作 → 心理状态 |
| 触发 | A 的事件/变化激活了 B | 财务离职 → 反脆弱思考 |
| 演化 | A 的演进推动 B 的演进 | 认知工程 → 意图工程命名 |
| 时序先后 | A 在时间上先于 B 出现，逻辑相关 | 涌现哲学 → 重构循环 |
| 无关系 | 两簇在 5 周内无任何交互 | 知识工程 ↔ 平台架构 |

### 输出

`data/output/inferred-relations.json`

```json
{

    {

      "relation_type": "支持",

    }

  },

  "previously_isolated_clusters_resolved": ["10"]

```

### 用户工作流

要让所有簇持续互联，用户的工作流是：

1. **每周写日志**（已在做）
2. 运行 `exp_infer` → LLM 读取最新分析报告，推断新关系
3. 审核推理出的关系（置信度 < 0.6 的标记为待确认）
4. 确认的关系并入 `intent-relation.yaml`
5. 图谱重建，覆盖率维持 100%

## 任务 7.2：全连接补全

### 实验意图

如果"所有想法都有内在关联"这个假设成立，那么当前图谱中 11 对"无关系"的簇对只是因为**未找到正确的证据和关系类型**，而非真正无关。补全策略需要回答：**对每一对簇，它们最具体的关系是什么？**

### 与任务 7.1 的区别

| 维度 | 7.1 exp_infer | 7.2 exp_complete |
|:----|:-------------|:----------------|
| 输入 | 分析报告（二手/摘要） | 原始日记文本（一手/原始） |
| 默认 | 无关系（直到有证据证明有关） | 有关（直到证据证明类型） |
| 关系类型 | 粗粒度（7 种） | 细粒度（支持/冲突/触发/演化/同框/时序/类比/组件/无关系） |
| 证据 | LLM 推理依据 | 原始文本引用 + 时空共现统计 |
| 输出 | 置信度分数 | 每条关系附带 N 条原始引用 |

### 关系类型（扩展）

新增"弱关系"类型处理无明显直接连接但对仍在同一思考空间中出现的簇：

| 类型 | 含义 | 证据标准 |
|:----|:-----|:--------|
| 支持/冲突/触发/演化 | 同 7.1 | 同一段落中明确提及两簇互动 |
| 情感补给 | 同 7.1 | 情绪性语言连接两簇 |
| **同框** | A 和 B 在同一周/同一天被提到，但无直接互动 | 时间窗口共现（同一日原文） |
| **时序** | A 在 B 之前出现，且逻辑上 A 的变化预示了 B 的出现 | 跨周轨迹追踪 |
| **类比** | A 和 B 用同一套隐喻或框架描述 | 共享核心术语（如"涌现"出现在研发和创作中） |
| **组件** | A 是 B 的组成部分 | 一个簇的目的/功能被另一个簇承载 |

### 方法

```
输入：原始日记（data/raw/2026-W{19,20,21,22,23}/*.md）
                    │
                    ▼
      按簇分组，对每对簇提取共现段落
                    │
                    ▼
     LLM 分析每对簇：时间线对齐 → 术语共享检测 → 
     互动模式识别 → 归类为最具体的关系类型
                    │
                    ▼
       输出：关系证据链（每对 N 条原文引用）
                    │
                    ▼
        用户审核引用 → 确认/细化关系类型
```

### 自查：实验意图 vs 设计

| 意图要求 | 当前设计 | 是否满足 |
|:--------|:--------|:--------|
| 假设所有想法都有关联 | 是，"有关"是默认值，找不到关系时降级为"同框"或"时序" | ✓ |
| 补全所有 45 对 | 对所有 C(10,2) 对执行，无筛选 | ✓ |
| 有关系类型分类法 | 扩展为 9 种类型，覆盖强弱关系 | ✓ |
| 有可验证的原始证据 | 每条关系附带原始日记引用，用户可直接审核 | ✓ |
| 避免 LLM 幻觉 | 引用可追溯，用户确认后才生效 | ✓ |
| 可增量维护 | 新周次加入后，新簇的新关系自动进入流水线 | ✓ |
