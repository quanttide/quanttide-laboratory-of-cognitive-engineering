# 项目七：LLM 驱动的隐含关系推理

## 问题

当前图谱中 10 个意图簇关系稀疏——簇5仅连接 2 个邻居，簇10完全孤立。但人类可读的分析报告（`assets/analysis/intent.md`、`intent-relation.md`）中包含大量隐含关系证据（事件触发、演化链、时序模式、冲突动态），这些从未被编码为图边。

**核心问题**：如何让所有簇相互关联起来？

## 方法：LLM 关系推理

用 DeepSeek 读取分析报告，为所有 45 个簇对推断隐含关系。

### 输入

- `assets/analysis/intent.md`：五周意图演化全景
- `assets/analysis/intent-relation.md`：意图关系分析
- `assets/refined/intent.yaml`：10 个簇的原始数据

### 推理引擎

`exp_infer` 二进制执行以下步骤：

1. 读取分析报告 + 簇定义
2. 构建提示词，要求 LLM 推断每对簇之间的隐含关系
3. 对每对关系输出：类型、方向、推理依据、置信度
4. 生成完整关系矩阵 JSON

### 关系类型

| 类型 | 含义 | 示例 |
|:----|:-----|:-----|
| 支持 | A 的存在促进了 B | 心理可持续 → 研发执行 |
| 冲突 | A 与 B 之间存在内在矛盾 | 商业高压 ↔ 心理可持续 |
| 情感补给 | A 为 B 提供情绪能量 | 创作 → 心理状态 |
| 触发 | A 的事件/变化激活了 B | 财务离职 → 反脆弱思考 |
| 演化 | A 的演进推动 B 的演进 | 认知工程 → 意图工程命名 |
| 时序先后 | A 在时间上先于 B 出现，逻辑相关 | 涌现哲学 → 重构循环 |
| 无关系 | 两簇在 5 周内无任何交互 | 知识工程 ↔ 平台架构 |

### 输出

`data/output/inferred-relations.json`

```json
{
  "inferred_relations": [
    {
      "from": 1,
      "to": 5,
      "relation_type": "支持",
      "direction": "单向",
      "evidence": "W22 POC 标准化模式确定后，商业模式验证加速",
      "confidence": 0.75
    }
  ],
  "coverage": {
    "total_pairs": 45,
    "with_relations": 40,
    "coverage_rate": 0.89
  },
  "new_edges_discovered": 35,
  "previously_isolated_clusters_resolved": ["10"]
}
```

### 用户工作流

要让所有簇持续互联，用户的工作流是：

1. **每周写日志**（已在做）
2. 运行 `exp_infer` → LLM 读取最新分析报告，推断新关系
3. 审核推理出的关系（置信度 < 0.6 的标记为待确认）
4. 确认的关系并入 `intent-relation.yaml`
5. 图谱重建，覆盖率维持 100%

## 运行结果

`exp_infer` 首次运行结果：

| 指标 | 值 |
|:----|:---|
| 分析簇对数 | 45 |
| 发现非空关系 | 34 |
| 覆盖率 | 100% |
| 簇10（原孤立）连接数 | 4 |
| 置信度最高 | 0.95（簇1↔簇2） |
| 置信度最低 | 0.35（簇4↔簇10） |

最关键的发现：**簇10（知识工程）通过簇3（认知工程）的演化关系被纳入图谱**（置信度0.80），不再是孤立节点。

关系类型分布：支持(26) > 演化(5) > 冲突(1) = 情感补给(1) = 触发(1)。
