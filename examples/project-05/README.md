# 项目五：图模型验证 + 进化测评

用 **全新技术数据**（W24+）验证方案A 和方案B，评估两个维度：
1. **检索能力**：有图比无图多发现了什么？
2. **图结构正确性**：推理路径是否反映了真实的思维流转？

## 数据

**测试集来源**：`../../../assets/raw/2026-W24/`（未参与图构建的全新数据）

**为何不用 W19-W23 做测试**：
- W19-W23 是图的训练数据，用它们做测试是循环验证（图不会"发现"已见过的东西）
- W24 是图从未见过的数据，才是真正的泛化检验

## 任务

### 5.1 人工构建 W24 基准

在执行测评前，先对 W24 原始日志做人工标注——类似 project-01 的流程但简化：

1. 阅读 W24 原始日志
2. 标注每段落的涉及意图（用已有 10 个簇的框架）
3. 标注段落间的因果/冲突关系
4. 输出 W24 mini 基准报告

**输出**：`data/baseline-w24.json`

```json
[
  {"segment": "原文段落", "clusters": [1, 3], "relations": [{"from": 1, "to": 3, "type": "支持"}]}
]
```

### 5.2 测试执行

将 W24 文本分别输入方案A 和方案B，收集输出。

**方案A**：
```bash
cat data/segments.txt | while read line; do
  echo "$line" | cargo run --bin approach_a -p project-03
done
```

**方案B（含反馈循环）**：先推理输出，审核候选边后更新图，再推理下一个段落。
```bash
for segment in data/segments-w24/*.txt; do
  cargo run --bin approach_b -p project-04 < "$segment" > "outputs/b-raw/$(basename $segment)"
  # 人工审核 candidate_edges → 更新 graph.json
  # 下一轮推理使用更新后的图
done
```

### 5.3 维度一：检索能力对比

与 W24 基准对照，看方案B 比方案A 多发现什么。

| 指标 | 定义 | 计算方式 |
|:----|------|---------|
| 正检率 | 方案B 正确识别的 intent 数 / 基准中总 intent 数 | 按 5 段平均 |
| 增量发现 | 方案B 识别到但方案A 未识别到的意图数 | 方案B - 方案A 汇总 |
| 误报率 | 方案识别到但基准不存在的意图数 / 方案识别总数 | 按 5 段平均 |

**关键问题**：额外发现的量以什么为代价？（误报数量 / 误报内容）

### 5.4 维度二：推理路径质量（图正确性）

方案B 输出的每条推理路径，由人类对照 W24 原文做判读：

| 等级 | 标签 | 说明 |
|:----:|------|------|
| 3 | 强洞察 | 路径揭示了原文中隐含的思维跳跃，且与作者实际思考一致 |
| 2 | 合理关联 | 路径在逻辑上成立，但属于常识推理 |
| 1 | 弱关联 | 路径在图上有边，但在原文语境中无意义 |
| 0 | 误推 | 路径在图上有边，但与作者的实际思考方向矛盾 |

**对照原文**：判读时打开 W24 原文，检查推理路径的每一步是否与作者的实际话题推进方向一致。

### 5.5 维度三：图进化追踪

记录方案的反馈回路效果：

| 指标 | 说明 |
|:----|------|
| 候选边提案数 | 每条推理生成的 candidate_edges 总数 |
| 审核通过率 | 人工保留的边 / 提案总数 |
| 图规模增长 | `graph.json` 的节点数和边数随推理轮次的增长 |
| 进化增益 | 图更新后，后续段落的推理质量是否提升（正检率变化） |

### 5.6 结论报告

**输出**：`outputs/evaluation.md`

- W24 基准摘要
- 检索能力对比表（正检率、增量发现、误报率）
- 推理路径质量评审表
- 图进化追踪（提案 → 审核 → 通过 → 增长链条）
- 整体结论：图模型是否真实反映了作者的思维模式？反馈回路能否让图持续变好？
