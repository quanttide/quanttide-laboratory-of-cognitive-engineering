# 测评解读报告

## 数据来源

使用 W23 的 5 段真实日志文本作为测试输入（非人工合成）。图谱从 W19-W23 数据构建，测试段来自 W23，属于**近循环验证**——不是严格的泛化检验（需要 W24+），但已能暴露系统短板。

所有数据见 `data/test-set.json`，完整测评结果见 `outputs/evaluation.json`。

## 逐个案例解读

### T1：AI 交互范式设计

> 我刚才在想，就是无论是代码编辑器还是文档编辑器，其实都不能够完全去适应当前 AI 的这种越来越多样和复杂的表达形式，及对它的交互的细节上的一些可能不是很适合，这这个就是我感觉我们可能需要或者说理论上存在一种新的交互方式，就是它和现在的这种交互方式会表面上差不多，可能还是三栏，但是在使用上可能会有一些本质区别。

**预期**：簇4（AI协作范式与人机分工）

**结果**：
| 方案 | 命中 | 正检率 |
|:----|:----|:------:|
| A | 簇4 | 100% |
| B | 簇4 | 100% |
| B 额外 | 簇4→簇3(支持)、簇3→簇4(支持) | 5条关系 |

**解读**：两方案都准确识别出"AI交互范式"话题。方案B 额外输出与簇3（认知工程）的双向支持关系——原文虽未明说"认知工程"，但这个关系在图谱中成立（AI协作与认知方法论互为支撑）。

---

### T2：意图工程

> 所有人类意图驱动的结构化生成过程，包括产品设计、架构设计等。这确实是我的直觉，被 AI 给讲清楚了。确实是抱着这个潜意识探究的。智谱提出了一个叫做意图工程的新概念，说我实际上发现了这个雏形。我确实有在考虑对意图建模，但是没想到居然可成为一门工程。确实很意外。

**预期**：簇3（认知工程与意图工程方法论）

**结果**：
| 方案 | 命中 | 正检率 |
|:----|:----|:------:|
| A | 簇4（误报） | 0% |
| B | 簇4（误报） | 0% |
| B 额外 | 簇4→簇3(支持)、簇3→簇4(支持) | 5条关系 |

**解读**：两方案都误判为簇4而非簇3。原因是文本中的"设计"、"架构"、"工程"等词与簇4的关键词重叠（簇4有"设计"、"架构"等 bigram）。**这是关键词匹配的固有限制**——"意图工程"这个核心概念在关键词表中不存在。

方案B 的额外关系虽然有 5 条，但因为起点是簇4（误报），所有推理路径都基于错误起点。不过，簇4→簇3(支持)这条边恰好将结果引向了正确的簇3方向——如果人工介入调整，簇3 的信息可以挽救。

**教训**：种子关键词覆盖不全时，匹配阶段的错误会污染推理阶段。

### T3：财务离职与团队反脆弱

> 财务突然离职，对我的心理造成了一些冲击。这加剧了我的不安感。我觉得我们得预防人突然跑路。这种时刻其实就是团队的反脆弱实验，就是说我们能不能维持住团队基本盘。

**预期**：簇2（心理可持续性）+ 簇8（团队建设与组织文化转型）

**结果**：
| 方案 | 命中 | 正检率 |
|:----|:----|:------:|
| A | 无 | 0% |
| B | 无 | 0% |
| B 额外 | 无 | 0条关系 |

**解读**：**最突出的失败案例**。"离职"、"财务"、"跑路"、"反脆弱"这些核心词在关键词表中一个都没有。关键词表是从 intent.yaml 的 per_week 表述中提取的，而 per_week 中用的表述如"搭建高效团队"、"维护心理稳态"——使用的是抽象、正面的学术语言，与作者的实际表达习惯（"跑路"、"不安"）存在巨大 gap。

这是关键词匹配最关键的瓶颈：**术语不等于作者用语**。

### T4：人机辩论与反思

> AI 在进行相互辩论的时候，会有一个特点，就是说如果没有人类干预的话，它就只能在一种状态之下收敛。然后人类的反馈丢进去过之后，会让 AI 跳出现有的框架。就我觉得这是一个很大的发现，就是怎么去定义反思，就是这种自己跟自己辩论，然后加入人类的反思，人人机反思或者人机辩论。

**预期**：簇3（认知工程）+ 簇4（AI协作）

**结果**：
| 方案 | 命中 | 正检率 |
|:----|:----|:------:|
| A | 无 | 0% |
| B | 无 | 0% |
| B 额外 | 无 | 0条关系 |

**解读**：文本涉及"反思"、"辩论"、"收敛"、"框架"等概念，既关联认知方法论（簇3）又关联 AI 协作（簇4），但关键词表对"反思"、"辩论"等词无覆盖。簇3 的 per_week 表述主要使用"认知工程"、"方法论"、"二阶控制论"等学术术语——与"辩论"和"反思"的关联在语义层面而非词汇层面。

**教训**：簇3（认知工程）是跨周主题（W19/W21/W22/W23），其表述在 4 周中用了完全不同的词汇——这说明**同一意图可以有多种词汇表达**，单靠关键词表无法覆盖全貌。

### T5：低耗能模式

> 这种低耗能模式之下，我的脑子里面只能去用一些现有的概念。如果我在这种状态下都能够维持产出的话，那么这个系统的自动化程度就非常高了，就是说我只要把想法吐出去就可以了，那么这样就可以极大地减少我发现新洞察的这种压力。

**预期**：簇1（研发方法论）+ 簇2（心理可持续性）

**结果**：
| 方案 | 命中 | 正检率 |
|:----|:----|:------:|
| A | 簇1 | 50%（漏了簇2） |
| B | 簇1 | 50%（漏了簇2） |
| B 额外 | 簇8→1(支持)、簇3→1(支持)、簇2→1(支持) | 3条关系 |

**解读**：两方案都检测到"低耗能模式"与簇1（研发方法论）的关联——"低耗能"、"产出"、"维持"、"自动"等 bigram 在簇1 的关键词表中。

簇2（心理可持续性）被漏掉了，因为文本没有使用"心理"、"压力"等直接词汇（虽然提到了"压力"这个词，但 cluster 2 的 per_week 表述用的是"心理可持续性"、"情绪调节"——"压力"不在关键词表中）。

方案B 的额外关系中，**簇2→簇1(支持)** 恰好是基准中标注的关系（心理→研发），但这来自图结构而非文本内容——图知道"心理状态是研发执行力的前提"。

## 模式识别

### 模式一：匹配阶段是瓶颈

5 个测试案例中，方案A 与方案B 的匹配结果**完全一致**（正检率均为 30%）。这是意料之中的——两方案共享相同的关键词表和匹配逻辑，瓶颈在匹配阶段，不在推理阶段。

### 模式二：推理阶段的增量价值明确

当匹配阶段成功时（T1、T5），方案B 稳定输出方案A 无法企及的关联信息（T1 输出 5 条关系，T5 输出 3 条）。当匹配阶段失败时（T3、T4），推理阶段无力回天——"巧妇难为无米之炊"。

### 模式三：术语 gap 是主要死因

关键词表从 per_week 表述构建，这些表述是**经过整理的学术语言**。但日志原文是**意识流自然语言**，两种语言风格差异巨大：

| 作者原文用语 | 关键词表中对应表述 |
|:-----------|:-----------------|
| "跑路"、"离职" | "搭建高效团队"、"反脆弱" |
| "辩论"、"反思" | "二阶控制论"、"认知工程方法论" |
| "压力" | "心理可持续性"、"可持续节奏" |
| "设计"、"架构" | "AI 协作范式"、"交互范式" |

### 模式四：图谱能"猜"出隐含关系

即使被测试文本未明确提及某个意图，图谱的边结构仍能推断出"文本涉及意图 X，而 X 与 Y 的关系是 Z"。这是关键词匹配做不到的。

## 量化总结

| 指标 | 值 | 含义 |
|:----|:--|:-----|
| 平均正检率 | 30% | 匹配阶段是主要瓶颈 |
| A/B 正检率差异 | 0% | 两方案匹配能力一致（公平对照） |
| 增量关系总数 | 13 条 | 方案B 发现的额外关联 |
| 平均误报率 | 20% | T2 的簇4 误报拉高了整体 |
| 匹配成功时的平均增量 | 4 条/段 | T1+T5 时方案B 稳定有效 |
| 匹配失败时的增量 | 0 条/段 | T3+T4 时推理无力回天 |

## 下一步方向

1. **关键词表改进**：从 per_week 表述扩展到包含作者实际用语。可以从原始日志中提取同义表达补充关键词表
2. **图结构验证**：需要 W24+ 数据做真正泛化检验——当前 W23 测试数据可能让指标偏高
3. **路径质量人工评审**：13 条增量关系需要逐条对照原文打标（强洞察/合理/弱相关/误推），确认哪些是真正有价值的发现
4. **语义匹配替代关键词匹配**：考虑用语义向量匹配替代关键词重叠，从根本上解决术语 gap 问题
