# 示例项目

本目录包含认知工程的各类示例项目和实验资产。

## 实验要求（2026-06-08）

### 核心目标
验证**意图**能否作为叙事工程的灵魂——在思考和想法之间产生一致性，类似母题在叙事中的关键作用。

### 实验数据
- **数据入口**：以最近一周的默认日志作为切入点（AI 与作者既陌生又熟悉，适合验证 AI 能否从想法中建立结构）
- **冷启动策略**：选择默认日志而非精心挑选数据，使冷启动条件更真实；先按话题分类（粗粒度过滤缩小搜索空间），再识别意图；使用一周数据窗口（足够产生模式，又不会信息过载）

### 建模重点
不仅识别意图，更要识别意图之间的结构（关系图），最终得到一个**意图及意图关系的领域模型**。

### 意图边界判定规则

**定义**：意图 = 对一个问题的持续关注模式，表现为日志中反复出现的同类关切。

**归属策略**：一条念头可能包含多个意图，按以下优先级处理：
1. **主标签 + 副标签**：标记最强的意图为主标签，其余为副标签
2. **拆分**：若一个念头包含两个无主次之分的意图，拆分为两条独立的意图记录
3. **多标签**：若一个念头均匀涉及多个意图，保留为多标签条目

**仲裁机制**：边界模糊时，执行因果链测试——问"这条念头在因果链上指向哪个问题的持续关注？"，指向明确则归属该意图；指向不明则标记为「待定」，积累更多上下文后重新判定。

### 意图层级体系

意图天然具有层级，人为限定两级（项目 → 任务）过于简化。实际使用**三级体系**：

| 层级 | 名称 | 判定规则 | 示例 |
|:----:|------|---------|------|
| L1 | 领域关切 | 影响范围跨越 3 个以上话题群，跨项目存在 | 认知工程、可持续性 |
| L2 | 核心议题 | 影响 1-3 个话题群，至少出现在 2+ 周日志中 | 研发方法、团队建设 |
| L3 | 单周验证 | 仅在当前分析窗口（1 周）的单个话题群内出现 | 某周的工具选型 |

**判定方法**：
- 先收集话题分类结果
- 统计每个候选意图出现的话题群数和周数
- 根据覆盖范围分配层级

**项目/任务映射**：项目 README 中的前置规划是**顶层假设**。当实际发现的意图层级与规划不匹配时，以**数据发现为准**（详见下方规划 vs 发现策略）。

### 实验组织
- 分级结构：**项目**和**任务**两级（替代之前的实验室/实验，实验室调整为 program 级别）
- 一个实验室（program）应产出单一结果
- 项目 README 中的规划是起点，而非约束——发现的结构有权推翻规划

### 方法论
1. 默认日志信息量大，先按**话题**分类——用粗粒度过滤缩小搜索空间
2. 以**意图为边界**区分话题——根据上述归属策略分配
3. 识别话题中的意图——应用三级层级判定
4. 提取意图间的关系——显式的关系建模步骤（见下方关系建模）
5. 意图逐步包裹为完整的想法
6. 重构周期在项目内统一管理

### 关系建模

关系提取是独立的方法论步骤，与意图识别并列。

**关系类型定义**：

| 类型 | 含义 | 示例 |
|:----|------|------|
| 支持 | A 的发生促进了 B | 研发方法论 ⊂ 认知工程（前者为后者提供工具） |
| 冲突 | A 与 B 的目标矛盾 | 研发效率 vs. 心理可持续性（加班 vs. 休息） |
| 依赖 | B 的成立以 A 为前提 | 商业模式 ⊂ 团队建设（好团队才有好产品） |
| 包含 | A 是 B 的一个子维度 | 认知负荷 ⊂ 认知工程 |
| 因果 | A 直接导致 B 的发生 | 商业验证 → 业务调整（验证结果推动方向变化） |

**关系发现方法**：
1. 对已识别的意图对，扫描同一周内的共现日志片段
2. 如果两个意图在一段日志中同时出现，根据上下文判断关系类型
3. 跨周追踪：同一对意图在不同周的关系可能变化——标注为 `stable`（固定）、`periodic`（周期性出现）、`situational`（单次上下文）

**演化机制**：关系图不是一次成型的。每周新日志进来，添加新节点和新边，已有关系可能强化（更多证据）、弱化（后续数据不支撑）、或撤销（后续数据否定）。

### 前置规划 vs. 渐进发现策略

**根本矛盾**：步骤 3（识别意图）的产出可能推翻步骤 1（前置规划）的假设。

**仲裁原则**：以**数据发现为准**（归纳优先），规划是可变假设。

**操作流程**：
1. 规划阶段：在项目 README 中写出顶层假设（预期的意图分类和关系）
2. 执行阶段：按方法论步骤操作，**如实记录发现**，即使与规划矛盾
3. 对齐阶段：执行完毕后，将发现的意图结构与规划对比
   - 若基本匹配 → 补充细节到 README
   - 若部分不匹配 → 修订 README 中的规划
   - 若完全不匹配 → 删除原规划，以发现的结构重写 README
4. 不强制意图结构适配前置规划——规划的价值在于提供一个**可证伪的起点**，而不是一个不可违背的蓝图
