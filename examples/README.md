# 实验规范

本目录存放认知工程的实验项目。每个实验验证一个具体假设，产出可提取到正式模块的代码或数据。

## 实验结构

每个实验是一个独立目录 `project-XX/`，包含：

```
project-XX/
├── README.md      ← 设计（输入、方法、输出）
├── Cargo.toml
└── src/
    ├── lib.rs     ← 可提取到 packages/rust/ 或 apps/ 的模块
    └── main.rs    ← 实验 binary
```

每个 README 中的设计是**起点假设**，允许被实验中发现的结构推翻。

## 实验流程

1. **设计**：在 `README.md` 写明输入、方法、输出格式
2. **审核**：用户确认设计后执行
3. **执行**：按设计产出代码和数据
4. **验收**：用户验收后提取可复用部分，清理实验目录
5. **提取**：可复用模块 → `packages/rust/`，正式工具 → `apps/`

## 命名规范

- 目录：`project-XX`（XX 为两位序号）
- lib 名：`project_XX`（Rust 自动映射）
- binary 名：`project-XX`

## 方法论原则

### 意图定义和边界判定

意图 = 对一个问题的持续关注模式。一条念头可能包含多个意图：

1. **主标签 + 副标签**：以最强意图为主标签
2. **拆分**：无主次之分的意图拆为独立记录
3. **多标签**：均匀涉及多个意图时保留多标签

边界模糊时执行因果链测试。

### 意图三级层级

| 层级 | 判定规则 | 示例 |
|:----:|---------|------|
| L1 领域关切 | 跨 3+ 话题群，跨项目存在 | 认知工程、可持续性 |
| L2 核心议题 | 1-3 话题群，2+ 周持续 | 研发方法、团队建设 |
| L3 单周验证 | 单周内单个话题群 | 某周工具选型 |

### 关系建模

意图之间的关系与意图识别并列，独立建模。类型包括：

- **支持**：A 促进 B
- **冲突**：A 与 B 目标矛盾
- **关联**：A 与 B 逻辑相关（含依赖、包含、因果、时序等子类型）
- **情感补给**：A 为 B 提供情绪能量

类别分为 `stable`（固定）、`periodic`（周期性出现）、`situational`（单次上下文）。

### 数据优先

规划是**可证伪的起点**。执行中发现的结构有权推翻规划——STATUS.md 记录已验证/未验证的 claims。
