# 项目四：方案B — 图谱推理 + 反馈回路

基于 petgraph 知识图谱的图遍历推理，且推理发现的新关联会反哺图结构。

## 定位

方案B 是**意图建模的核心**：不仅用图做推理，还用推理结果让图成长。

方案B 与方案A 共享完全相同的匹配逻辑（用同一个 `keywords.json`），差异在于方案B 在匹配之后多做了两步：**图遍历推理** + **反馈回图**。

## 任务

### 4.1 构建初始图谱

从 YAML 加载、构建 petgraph 有向图。

**输入**：`../../../assets/refined/intent.yaml` + `../../../assets/refined/intent-relation.yaml`

**方法**：有向图 `Graph::new_directed()`，"支持"/"依赖"边方向保留，"冲突"边视为双向，"包含"边从父指向子。

**输出**：`data/graph-init.json` + `src/graph.rs`

### 4.2 推理引擎

接收文本 → 输出匹配节点 + 推理路径 + 冲突 + 候选新边。

**算法**：
1. **节点匹配**：调用与方案A 相同的关键词表（共享 `keywords.json`），匹配起始节点
2. **邻居发现**：列出所有直接邻居及边方向
3. **多跳路径**：BFS 遍历 2 跳（若图小可满 1 跳），输出路径
4. **冲突检测**：直连冲突边 + 通过中间节点的间接冲突（2 跳路径中边方向指向冲突的路径）
5. **候选新边生成**：若两个匹配节点在图中间接相连（2 跳），且路径上下游关系合理，生成一条候选边

**输出**：stdout JSON

```json
{
  "match_nodes": [{"id": 1, "name": "研发方法论", "evidence": ["研发", "效率"]}],
  "neighbors": [{"from": 1, "to": 2, "relation": "支持", "logic": "xxx"}],
  "bfs_paths": [
    [{"from": 1, "to": 3, "relation": "支持"}, {"from": 3, "to": 5, "relation": "冲突"}]
  ],
  "conflicts": [{"node_a": 1, "node_b": 5, "via": [3]}],
  "candidate_edges": [
    {"from": 1, "to": 5, "proposed_type": "冲突", "evidence": "经由节点3的传递冲突", "confidence": 0.7}
  ]
}
```

### 4.3 反馈回路（核心新增）

推理产出的候选边经人工审核后，并入图谱。

```
输入文本 → 推理 → 候选边 → [人工审核] → 通过 → 更新 data/graph.json
                                        → 拒绝 → 记录到 reject_log（防止重复提案）
```

**审核标准**：
- 保留：候选边反映了真实的思维关联，且不是直觉跳跃（有日志原文支撑）
- 拒绝：候选边技术上成立但实际意义不大，或在文本上下文中不成立

**更新后**：持久化到 `data/graph.json`，下次推理在此基础上继续。

**源码**：`src/graph.rs` + `src/main.rs`
