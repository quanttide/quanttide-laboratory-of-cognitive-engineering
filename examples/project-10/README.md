# 实验 project-10：意图即母题 — 跨簇共鸣

## "意图即母题"的含义

### 关键纠正：母题不是作者刻意安排的

我最初预设了母题是**作者刻意安排**的。但文学中大量母题恰恰是**无意识流露的**——作者不是在"安排母题"，而是某个意象反复出现在笔下，他自己甚至没意识到。

> 一个人写日志时不是在"记录意图"，就像一个人在写作时不是在"安排母题"——但回看时，**结构在那里**。

两者都是**事后才能识别的模式结构**，不是**事前安排的计划**。都是主体行为中自然涌现的深层结构，都需要通过逆向工程才能识别。这也是整个实验的出发点。

### 母题的三层

1. **母题不是标签，是变奏的统一体**——"低耗能"在簇1是"POC模板化"，在簇2是"滑翔状态"。关键词不同，场景不同，但属于同一个关切的两种变奏。
2. **关键词匹配永远抓不住母题**——"心理预算"和"POC模板"没有共同关键词，但属于同一个母题。project-09 的根本瓶颈不是覆盖面不够，是匹配粒度错了。
3. **母题是你的一致性引擎**——"元"出现在簇1/3/4，被关键词分散在不同轮次里，但它们的共同本质在一句话里就点透了。

### 实践含义

> 脚手架应该能回答"这个新想法在变奏哪个已有的关切"，而不是"这个新想法匹配哪个已有的关键词"。

## 核心命题

> **意图不是检索用标签，而是母题——一个持续关切的模式，在显式无关的想法之间产生连贯性。**

## 重新审视后的设计问题

当前的设计（A. 查收敛表 + B. 展示历史变形 + C. 找原型共鸣）仍然把母题当成了**查表**：

| 机制 | 实际行为 | 隐含假设 |
|------|---------|---------|
| A | 从 `derived_insights.convergences` 表里查已有主题 | 母题已存在且已编目 |
| B | 展示预提取的周粒度意图列表 | 母题的变形已录入 |
| C | LLM 单独找类比（脱离图谱） | 母题的普遍性不需要图来验证 |

三个机制是割裂的，没有一个统一的"发现流程"。真正的母题发现不应该查表——应该让 LLM 穿越图谱，**识别出一个从未被编码为边的深层关联**。

## 新设计：关切追踪（Concern Tracing）

### 统一流程

```
用户输入
  → 1. LLM 提取"潜在关切"——用户没明说但隐含的持续担忧
  → 2. 扫描所有 10 个簇，由 LLM 判断：
        "这个簇的核心意图是否表达的是同一个潜在关切？"
  → 3. 返回母题报告：
        "这个关切之前出现过 3 次——
         在簇1表现为「POC模板化」，
         在簇2表现为「滑翔状态」，
         在簇9表现为「通过写作恢复能量」。
         每一次是同一个关切的不同变奏。"
  → 4. LLM 判断：这是已有母题的新变奏，还是一个前所未有的新母题？
```

### 与 project-09 的关键区别

| 维度 | project-09（检索式） | project-10（母题式） |
|------|--------------------|--------------------|
| 匹配对象 | 输入文本 vs 关键词索引 | 输入文本 vs **所有簇的核心意图**（LLM 语义判断） |
| 检索粒度 | bigram/keyword overlap | **潜在关切**匹配——跨关键词、跨语法、跨场景 |
| 输出核心 | positioning / connections / exploration | **母题发现**：一个关切在多个簇的变形轨迹 |
| 历史利用 | 已探索簇得高分 → 收敛 | 已发现关切关联的簇被激活 → 发散 |
| 冷簇 | 从未匹配到的簇中随机选 | **已经表达了同一个关切但未被检索到的簇**自动浮现 |

### 一个关键变化：从匹配到关切

project-09 的匹配机制是：

```
keyword overlap → top 4 curated clusters
```

project-10 的匹配机制是：

```
LLM extracts latent concern → search ALL clusters → cluster returns if it embodies the same concern
```

这意味着**不再需要 bigram/keyword 匹配码**。匹配的载体从关键词变成 LLM 的语义判断。匹配的目标从"关键词重叠的簇"变成"体现同一个底层关切的簇"。

### 流程细节

**第 1 步：提取潜在关切**

LLM 从用户输入中提炼一个"关切断言"——不是簇名称，不是关键词，而是深层的、持续的担忧或追求。

```
输入："交付前需要大量POC，所以需要提高POC质量。心理压力主要来自POC太混乱"
→ 潜在关切：如何在混乱和压力下保持有效产出
```

**第 2 步：扫描全图**

对所有 10 个簇，LLM 逐个判断：
- 这个簇的核心关切是否与"如何在混乱和压力下保持有效产出"本质相同？
- 如果是，给出证据（该簇的哪些意图表达了这一点）
- 按相关度排序

**第 3 步：生成母题报告**

```json
{
  "motif_statement": "在混乱和压力下保持有效产出",
  "is_new_motif": false,
  "variations": [
    {"cluster_id": 1, "form": "POC模板化、CLI工具化、减少决策负荷", "week": "W23"},
    {"cluster_id": 2, "form": "滑翔状态、心理预算、制度对冲", "week": "W22"},
    {"cluster_id": 9, "form": "通过虚构写作恢复创造能量", "week": "W21"}
  ],
  "motif_arc": "这个关切最早在W21以「创造能量恢复」的形式出现(W9)，W22转入「心理预算与制度对冲」(W2)，W23落地为「POC模板与低耗能工具」(W1)。当前输入回到了W22的阶段——你又在处理混乱与压力的关系，但这次指向了工具化解决方案。",
  "positioning": "...",
  "connections": "...",
  "exploration": "...",
  "discovery_update": {...}
}
```

**第 4 步：判断新/老母题**

- 如果已有 2+ 个簇表达了同一个关切 → 已有母题，当前输入是其新变奏
- 如果只有一个或零个 → 可能是新母题，建议关注后续是否重复出现

### 中止条件

1. MAX_TURNS = 16
2. 连续 2 轮无新母题发现
3. 用户 exit

| 指标 | 测量方式 | 与 09 对比 |
|------|---------|-----------|
| 母题发现数 | 每轮新增 `motif_statement` 数量 | 09 无此维度 |

## 实验结果（2026-06-08，5 轮）

| 指标 | project-09 | project-10 |
|------|-----------|-----------|
| 已探索簇覆盖率 | 4/10（关键词匹配 top 4） | 7/10（全图语义扫描） |
| 跨簇关联深度 | 最大 2 簇（通过边） | 最大 5-7 簇（通过母题） |
| 新边发现 | 每轮 1-2 条已有 session 边 | 无（改用母题发现，不依赖边） |
| 连贯性类型 | 历史粘性（同一簇反复出现） | 母题驱动（同一个关切跨簇穿行） |
| 能否识别无意识模式 | 否（只匹配已编目关键词） | 是（提取用户未明说的潜在关切） |

### 关键差异

1. **project-09 的"连贯性"是伪连贯性**——同一簇反复出现是因为历史偏置匹配（score × 1.5），不是因为它真的和上次有关。project-10 的连贯性是真正的主题连贯——母题报告明确说"这个关切之前出现过 N 次，在簇X作为Y，在簇Z作为W"。

2. **project-09 需要用户自己切换簇**——用户输入变了，匹配才变。project-10 能同时看到多个簇中的同一个关切，用户不需要"想到"切到哪个簇。

3. **元认知跃迁只有 project-10 捕获了**——第 4 轮"元模式"洞察出现时，project-10 的母题弧自动追溯了从 W19 到 W23 的完整演化。project-09 只是把它当作又一个 cluster-1 输入。
