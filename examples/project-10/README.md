# 实验 project-10：意图即母题 — 跨簇共鸣

## "意图即母题"的含义

### 第一层：母题不是标签，是变奏的统一体

"低耗能"在簇1表现为"POC模板化、CLI工具化、减少决策负荷"，在簇2表现为"滑翔状态、心理预算、制度对冲"。关键词完全不同，语法不同，场景不同——但两者是同一个关切（如何用最小能量维持产出）的两种变奏。就像贝五的"命运动机"可以在大调、小调、弦乐、铜管上出现，你仍然认得出它。

### 第二层：关键词匹配永远抓不住母题

当前 scaffold 的匹配机制是 `bigram/keyword overlap → top 4簇`。"心理预算"和"POC模板"没有共同 bigram，所以系统看不到它们是一个母题的两面。这就是 project-09 停在 4/10 簇的根本原因——不是覆盖面不够，是匹配粒度错了。

### 第三层：母题才是你的一致性引擎

你说过"当前研发是元模式——不是在做产品，是在做产生产品的方法"。"元"出现在簇1（元模式研发）、簇3（元认知工程）、簇4（元协作范式）。这三个簇被关键词检索分散在不同的轮次里，但它们的共同本质在一句话里就点透了——因为你识别出了母题，而检索系统没有。

### 实践含义

> 脚手架应该能回答"这个新想法在变奏哪个已有的关切"，而不是"这个新想法匹配哪个已有的关键词"。

## 核心命题

> **意图不是检索用标签，而是母题——一个持续关切的模式，在显式无关的想法之间产生连贯性。**

project-09 验证了多轮累积能加深探索，但它的"连贯性"来自**历史粘性**（同一簇反复出现），而不是**意图驱动**（一个深层关切在不同簇之间穿针引线）。

实验 10 要验证：如果脚手架的核心机制从「检索匹配」换成「母题发现」，能否产生更有深度的跨簇连贯性。

## 问题

| project-09 的局限 | 根因 |
|------------------|------|
| 跨簇跳转靠用户输入，不是系统主动发现 | 匹配机制是检索式的，不是意图式的 |
| LLM 只能回答"这个输入匹配哪些簇" | 没有机制让它回答"这个输入**意图指向**哪些簇" |
| 外部视角是额外字段，不是核心机制 | LLM 自己的知识库和日志亮点的价值被边缘化 |

## 设计

### 三项变更（从「检索」到「母题」）

| 变更 | project-09（检索式） | project-10（母题式） |
|------|--------------------|--------------------|
| 冷注入 | 随机选一个未匹配簇 | **意图驱动**：从 derived_insights.convergences 中选择与当前探索轨迹共振但未被触及的簇 |
| 日志亮点 | 为匹配簇附带原始语录（装饰性） | **意图变形展示**：展示同一个意图在不同周的不同表达形态，让 LLM 识别"核心关切不变，表层语言在变" |
| 外部视角 | LLM 引入图外类比（可选字段） | **原型共鸣**：LLM 识别用户当前的意图模式在人类知识/文化/历史中的对应物，验证意图的普遍性 |

### A. 意图驱动冷注入（取代随机冷注入）

不从全部未匹配簇中随机选，而是从 `derived_insights.convergences` 中选：

```rust
fn motif_inject(&self, current_ids: &[u32], state: &DiscoveryState) -> Option<Inject> {
    // 找出与当前簇共享收敛主题但未探索的簇
    // 例：当前在簇1（低耗能）→ 簇2（低耗能正式化）也在 convergences 中
    //     → 注入簇2，并告知共享主题"低耗能"
    for conv in &self.data.derived_insights.convergences {
        let shared = conv.clusters.iter().filter(|id| current_ids.contains(id)).count();
        let cold: Vec<&u32> = conv.clusters.iter().filter(|id| 
            !current_ids.contains(id) && !state.explored_clusters.contains(id)
        ).collect();
        if shared > 0 && !cold.is_empty() {
            return Some(Inject { id: *cold[0], theme: conv.theme.clone() });
        }
    }
    None
}
```

提示词标注：**「🎵 母题连接：当前想法与簇X共享「{主题}」主题——同一个关切的不同变奏」**

### B. 意图变形展示（日志亮点升级版）

不是随机摘一句语录，而是按周展示同一个意图的语言演变：

```
簇1「研发方法论与工具链」的意图变形：
  W19: "建立以涌现为核心的快速研发方法论" — 哲学化表达
  W20: "建立以重构为中心的研发体系" — 体系化表达
  W21: "搭建多语言自动化研发工具链" — 工具化表达
  W23: "利用低耗能模式维持产出" — 模式化表达

核心关切始终是「如何高效地产出」，但表层语言从哲学→体系→工具→模式。
```

提示词任务：**「识别当前输入落在该意图的哪个变形阶段，或是否开启了新的变形」**

### C. 原型共鸣（取代通用外部知识）

不是让 LLM 随意引入类比，而是识别用户的意图模式在人类认知中的**原型对应**：

```
你识别出的意图模式「低耗能创造循环」与以下人类知识共鸣：
- 道家「无为而治」：最小干预下的自然产出
- 编程中的「懒惰程序员」哲学：好的工具减少重复劳动
- Mihaly Csikszentmihalyi 的「心流」理论：技能与挑战的平衡点
```

提示词要求：
1. 识别当前对话中的意图模式
2. 找到 1-2 个文化/学术/历史中的对应原型
3. 说明共鸣点在哪（不是随便贴标签）

## 评估

| 指标 | 测量方式 |
|------|---------|
| 母题采纳率 | LLM 在 exploration 中主动使用注入母题的比例 |
| 意图变形识别 | LLM 是否识别出当前输入与历史表达的变形关系 |
| 原型共鸣质量 | 共鸣是否具体（不是泛泛类比）|
| 跨簇深度 | 从入口簇出发，经几次母题跳转到达最远簇 |
