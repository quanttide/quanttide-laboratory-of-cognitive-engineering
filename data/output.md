# 新图式：图式转移方法

从创始人的认知工程数据出发，手动迁移到客户问题后找到的新图式。

---

## Entities

| 实体 | 属性 |
|------|------|
| 源图式 | domain, entities, causals, boundaries, mappings, biases |
| 目标问题 | 领域, 约束, 预期产出 |
| 映射操作 | 源结构, 目标结构, 推理路径 |
| 映射类型 | 同构, 隐喻, 反例, 约束 |

## Causals

- 源图式与目标问题结构同构 → 保留关系方向，替换具体实体
- 源图式是隐喻类比 → 验证核心约束后在目标域中找功能对等物
- 源图式含 biases（信念→事实） → 直接复制为"避免的陷阱"
- 源图式有 boundaries → 检查目标是否在约束范围内，否则标为不可迁移

## Boundaries

- 适用于：已有结构化认知数据（YAML 图式）的场景
- 排除：无原始数据、目标问题与源领域完全无关
- 需要：至少 2 个以上源图式才能提炼映射类型
- 限制：创始人的个人认知情境（一人+AI）迁移到团队情境时需要适配

## Mappings

| 意图 | 行动 |
|------|------|
| 从原始数据中提取图式 | YAML 解析 → entities/causals/boundaries/mappings/biases |
| 判断映射类型 | 检查源与目标的结构相似度 → 同构/隐喻/反例/约束 |
| 记录映射过程 | 每步记录推理路径（保留/丢弃了什么、为什么） |
| 分类映射结果 | 按映射类型分组而非按目标问题阶段分组 |
| 打包为方法 | 将转移规则写为 IF-THEN 程序 |

## Properties

| 属性 | 值 |
|------|-----|
| 核心假设 | 认知结构可跨域转移，转移路径可记录为程序 |
| 复用性 | 映射类型规则可复用；映射具体值不可复用 |
| 验证方式 | 用方法重新做一次转移，比较两次结果是否一致 |

## Dynamics

| 维度 | 趋势 |
|------|------|
| 方法完整性 | 随验证次数递增（当前验证 6/10，缺 dynamics 和 properties 映射规则） |
| 自动化程度 | 从全人工逐步过渡到代码+LLM+人工三层协同 |

## Biases

| 信念 | 事实 |
|------|------|
| 映射的目标是解决客户问题 | 映射的目标是记录转移方法 |
| 产出一个好方案就是成功 | 方案是验证材料，可复现的方法才是产出 |
| 结果正确就够了 | 过程可复查比结果正确更重要 |
