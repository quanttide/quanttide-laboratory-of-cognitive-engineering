# 映射决策日志

复盘"提取源图式 → 映射到技术升级"的完整过程，记录每个关键决策点。

---

## 分岔点 1：选中了错误的目标问题

**位置**: Step 2 开始前  
**决策**: 将"技术升级"作为映射目标  
**实际应该**: 将"转移方法论本身"作为产出目标  
**原因**: 

TODO.md 的 Step 2 写的是"这个结构在技术升级上对应什么？"。这个提问的语法（"在 X 上对应什么"）已经预设了 X 是最终目的地。当 X = 技术升级时，整个后续工作就变成了"解决技术升级问题"，而不是"记录从源到 X 的转移程序"。

**规则**: 问句预设了答案的类型。"这个结构在 X 上对应什么"产出的是一组映射关系；正确的问题应该是"这个结构的转移方式有什么可复用的模式"——产出的是方法。

---

## 分岔点 2：把"映射"当成了终点而非过程记录

**位置**: 写 migration-map.md 时  
**决策**: 为 9 个 domain 各自找了一个"在技术升级上的对应物"  
**实际应该**: 记录"我是怎么从源结构想到那个对应物的"

migration-map.md 的每一条都是结果，没有过程。比如：

```
infra 被动防守→主动设计 → 从救火式运维转向体系化治理
```

**缺失的信息**:
- 为什么这个映射成立？（因为 infra 的问题结构——"当前状态差、目标状态好、中间有路径"——和技术升级同构）
- 迁移时保留了结构的什么？（保留了"从状态 A 到状态 B 的转型方向"）
- 迁移时丢弃了什么？（丢弃了"备份策略"、"工具链"等具体技术细节）

如果记录了这些，产出的就是方法（"当源 schema 是一个转型叙事时，保留方向映射，丢弃具体手段"），而不是方案。

## 分岔点 3：过早合成"框架"

**位置**: Step 3  
**决策**: 把 9 个映射结果按"哪个阶段做什么"组织为一个线性的 6 层框架  
**实际应该**: 按"映射方式相同"分类，提炼映射模式

6 层框架（范式认知→评估→策略→路径→治理→节奏）是**对客户问题的解决方案结构**，不是**对转移方法的结构**。

如果按映射方式分类：

| 映射方式 | 涉及的 domain | 复用性 |
|---------|-------------|--------|
| **结构同构**（A:B ≈ C:D） | infra → 技术, org → 组织 | 高——问题结构直接对应 |
| **隐喻迁移**（X 就是 Y） | innov → business, business → 商业 | 中——需要确认跨域有效性 |
| **反例学习**（不要做什么） | biases 中的信念→事实 | 高——否定性知识更易迁移 |
| **约束条件**（在什么条件下成立） | boundaries | 高——决定了哪些不能迁移 |

这才是方法论层面的产出：**识别映射类型 → 每种类型有其转移规则**。

## 分岔点 4：用方案验证方法

**位置**: Step 4  
**决策**: 产出一个完整的 upgrade-plan.md + 报价，作为"验证"  
**实际应该**: 用方法重新做一次转移（相同问题），比较两次过程

upgrade-plan.md 的问题不是它错了，而是它作为验证材料**无法验证任何东西**。它用一次性的直觉产出，没有步骤记录、没有决策依据、没有与方法的对照。

正确验证应该是：
1. 有一个明确的转移方法（步骤清单）
2. 按照方法再做一次转移
3. 比较两次输出的差异 → 方法是否可复现？

---

## 关键教训

| # | 教训 | 规则 |
|---|------|------|
| 1 | 问题问错了，后续全偏 | 目标问题应是方法论本身，而非客户问题 |
| 2 | 记录结果不记录过程 | 产出应是过程的可复现模式，而非一组映射值 |
| 3 | 按问题域合成而非按方法域合成 | 分类轴应是"映射方式"而非"解决方案阶段" |
| 4 | 无法验证的一次性产出 | 验证需要"用方法再做一次"，而非"拿出结果" |

---

## 反事实：正确路径应该是什么样的

```
提取源图式（Step 1 ✓）
    │
    ▼
记录映射决策（Step 2 重写）
    │  对每个 domain：记录"我是如何找到对应物的"
    │  → 提炼出映射操作的原子步骤
    │  → 识别映射类型（同构/隐喻/反例/约束）
    │
    ▼
按映射类型分类（Step 3 重写）
    │  不是合成框架，而是抽象出"每种映射类型的转移规则"
    │  → 结构同构映射：保留关系结构，替换具体实体
    │  → 隐喻映射：验证核心约束是否匹配
    │  → 反例映射：直接复制否定性知识
    │  → 约束映射：标记不可迁移的边界条件
    │
    ▼
打包为可执行方法（Step 3 输出）
    │  一个手工可执行的步骤清单
    │
    ▼
验证（Step 5）
    │  用这个方法重新做一次转移
    │  比较两次过程与结果
```
