# 源图式清单

基于 `data/journal/quanttide-founder/2026-W23/` 中 9 个 domain 的 YAML 文件提取。

---

## 1. think — 认知工程（核心方法论）

**语境角色**: 整个系统的核心方法论引擎。定义了一切结构化生成的底层机制——意图工程。

| 维度 | 内容 |
|------|------|
| **Entities** | 人类意图（驱动、反馈）↔ 辩论（收敛、章程生成） |
| **Causals** | ① 人类反馈打破 AI 局部最优 → 辩论收敛 ② 辩论产出章程 → 获得结构化知识 |
| **Boundaries** | 适用于人机协同；排除单机推理；需要以章程为辩论目标 |
| **Mappings** | 发现意图 → 进行人机辩论；生成章程 → 将辩论产物结构化 |
| **核心命题** | 人类反馈是打破框架的关键，AI 无法自行收敛到最优 |
| **角色** | **收敛机制** — 将发散探索结构化为可复用的知识（章程） |

---

## 2. innov — 创新管理（POC 范式）

**语境角色**: 快速探索引擎。通过低成本试错替代大规模规划，与 think 的收敛形成互补。

| 维度 | 内容 |
|------|------|
| **Entities** | 人类（洞察供给、反馈质量）↔ AI（补全能力、整合能力） |
| **Causals** | ① 人类提供充足洞察 → AI 有效补全并整合 ② AI 整合完成 → 驱动下一轮上升循环 |
| **Boundaries** | 适用于研发探索；排除纯机械重复任务；需要 AI 达到可补全的质量 |
| **Mappings** | 快速发现洞察 → 启动 POC，AI 作为补全器；维持低耗能产出 → 依赖 AI 自动化 |
| **核心命题** | 人机互补循环——人类提供方向，AI 加速执行 |
| **角色** | **发散引擎** — 大量 POC 低成本试错，驱动上升循环 |

---

## 3. org — 组织管理（人治→法治转型）

**语境角色**: 组织韧性管理。核心矛盾是制度化 vs 保留温度——提升稳健性时不能丢失文化。

| 维度 | 内容 |
|------|------|
| **Entities** | 团队（韧性、人治温度）↔ 制度（法治、标准化） |
| **Causals** | ① 依赖人治 → 组织温度高但脆弱 ② 建立制度且保留弹性 → 韧性增强且温度不骤降 |
| **Boundaries** | 适用于中小型组织（5-50人）；排除成熟大企业；需要创始人敏感度 |
| **Mappings** | 应对人员流失 → 建立反脆弱机制；文化转型 → 法治与人治同步推进 |
| **核心命题** | 制度化是根本，但温度损失可通过叙事和文化机制对冲 |
| **角色** | **抗脆弱机制** — 在冲击下维持基本盘，同步推进法治与人治 |

---

## 4. infra — 基础设施（被动→主动）

**语境角色**: 技术底座治理。从救火式运维升级为体系化主动设计。

| 维度 | 内容 |
|------|------|
| **Entities** | 基础设施（备份策略、工具链归属、架构边界）↔ 治理体系（标准化、自动化、分工） |
| **Causals** | ① 被动防守备份且工具链归属不清 → 数据丢失风险和维护负担增加 ② 主动设计体系 → 安全可靠平台 |
| **Boundaries** | 适用于多云端环境；排除单机简单场景；需要至少三个实例才进入抽象层 |
| **Mappings** | 防数据丢失 → 建立自动化备份；理清工具链归属 → 标准化治理 |
| **核心命题** | 体系化治理比堆叠备份更有效；过度抽象本身也是风险 |
| **角色** | **平台底座** — 为上层创新提供安全稳定的实验环境 |

---

## 5. meta — 元职能（标准化治理）

**语境角色**: 系统自我维护能力。标准化的终点不是规则文档，而是系统自我维护的元能力。

| 维度 | 内容 |
|------|------|
| **Entities** | 元智能（标准化、自我维护）↔ 系统（成熟度、规则依赖） |
| **Causals** | ① 元智能成熟 → 系统自我维护 ② 元智能不成熟 → 规则依赖人工维护 |
| **Boundaries** | 适用于系统治理体系；排除一次性规则制定；需要系统运行至少三个月 |
| **Mappings** | 建立标准化 → 归并冗余规则集；提升系统成熟度 → 培养元智能而非推动标准化本身 |
| **核心命题** | 标准化是元智能的自然产出，不是终点工作 |
| **角色** | **治理层** — 标准化沉淀为系统自我维护的能力，降低维护负担 |

---

## 6. health — 身心健康（元意图）

**语境角色**: 所有其他意图的基础前提。不直接驱动工作，而是保障一切可持续运作。

| 维度 | 内容 |
|------|------|
| **Entities** | 元意图（可持续性、维护状态）↔ 工作意图（探索状态、产出质量） |
| **Causals** | ① 元意图得到维护 → 工作意图可持续运作 ② 元意图被忽视 → 高压探索产生无意义感 |
| **Boundaries** | 适用于高压探索阶段；排除短期冲刺场景；需要操作者对自身有觉察能力 |
| **Mappings** | 保持心理可持续 → 早睡早起并切换到低耗能模式；对冲无意义感 → 执行整合 |
| **核心命题** | 高压探索的固有产物是无意义感，无法消除只能对冲 |
| **角色** | **元意图（基础层）** — 保障所有其他意图持续运作的前提条件 |

---

## 7. business — 商务拓展（POC 同构）

**语境角色**: 商业探索。与 innov 的研发 POC 范式同构——低门槛验证，可行后复制。

| 维度 | 内容 |
|------|------|
| **Entities** | 新想法（可行性、门槛）↔ 验证手段（POC、章程、原型） |
| **Causals** | ① 新想法通过低门槛验证 → 可行后结构化复制 ② 验证失败 → 低成本放弃 |
| **Boundaries** | 适用于商业和研发探索；排除高投入长期项目；验证周期不超过两周 |
| **Mappings** | 探索新商业模式 → 做 POC 验证；降低风险 → 先小规模试错 |
| **核心命题** | 验证成功只是技术可行，商业价值需要独立评估 |
| **角色** | **商业 POC** — 将 innov 的 POC 范式迁移到商业模式探索 |

---

## 8. product — 产品研发（范式重构）

**语境角色**: 交互范式升级。当现有工具无法适应新能力边界时，需要范式级重构而非 UI 优化。

| 维度 | 内容 |
|------|------|
| **Entities** | AI 表达（多样化、超越传统）↔ 交互范式（阅读器、编辑器、块编辑器） |
| **Causals** | ① AI 表达超越传统文档边界 → 传统编辑器不适应 ② 从阅读器角度重新设计 → 适应 AI 协作 |
| **Boundaries** | 适用于 AI 协作场景；排除传统文档编辑；需要 AI 底层操作足够可靠 |
| **Mappings** | 适应 AI 表达 → 设计可编辑阅读器；缓解 AI 注意力不足 → 分解组件分别设计 |
| **核心命题** | 不是 UI 技巧问题，需要范式级重构 |
| **角色** | **范式迁移** — 技术方案到范式认知的演进 |

---

## 9. write — 叙事工程（原型→框架迭代）

**语境角色**: 创作工具链。从原型验证到框架成型的迭代过程，整合的力量驱动上升循环。

| 维度 | 内容 |
|------|------|
| **Entities** | 写作云（原型、框架）↔ 方法论（3R、本体关系） |
| **Causals** | ① 原型验证可行 → 框架成型 ② 整合力量驱动 → 上升循环推进 |
| **Boundaries** | 适用于叙事工程；排除非结构化写作；需要足够碎片积累后才能整合 |
| **Mappings** | 打磨写作云 → 从原型到框架迭代；驱动上升循环 → 利用整合力量 |
| **核心命题** | 框架不能一次性建成，需要从原型迭代成型 |
| **角色** | **迭代引擎** — 碎片→整合→框架的成长循环 |

---

## 跨 domain 模式

| 模式 | 出现 domain | 核心结构 |
|------|------------|----------|
| **POC→复制** | innov, business | 低成本验证 → 可行后结构化复制 |
| **收敛 vs 发散** | think, innov | 辩论收敛（结构化）↔ POC 发散（试错） |
| **被动→主动** | infra, org | 防守响应 → 主动设计 / 应急 → 制度化 |
| **元意图** | health, meta | 不直接产出，保障其他一切可持续 |
| **原型→框架** | write, product | 从碎片/原型迭代成型 |
| **人机协同** | think, innov | 人类提供方向/反馈，AI 加速执行/补全 |
