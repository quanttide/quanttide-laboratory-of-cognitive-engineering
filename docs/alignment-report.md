# 理论对齐报告：图式理论 vs Lab Schema 定义

对照来源：`library/theories/schema-theory.md`（Bartlett/Piaget/Rumelhart）

## 逐字段对照

| Lab 字段 | 理论对应概念 | 对齐程度 | 判定 |
|---------|-------------|---------|------|
| `usage` | 无直接对应 | — | **设计决策**：lab 为每个 schema 显式标注适用场景，理论不关心此维度 |
| `entities` | 知识封装（知识封装） + 层次组织（层次组织） | 部分对齐 | **设计决策**：lab 用 entities + attributes 表达知识封装，但没有建模子图式层级 |
| `causals` | 主动选择（主动选择）——图式决定哪些信息被注意和如何解释，导致特定推理路径 | 部分对齐 | **设计决策**：lab 将因果链显式为 condition→outcome 对，理论描述的是机制而非形式 |
| `boundaries` | 无直接对应 | — | **设计决策**：理论中边界是隐式的（图式自然不适用某些场景），lab 显式列出适用/排除条件 |
| `properties` | 默认值填充（默认值填充）——信息缺失时图式提供默认值 | 部分对齐 | **设计决策**：key-value 对能表达默认值，但缺少"当 X 缺失时默认为 Y"的语义标记 |
| `dynamics` | 图式生命周期（形成→强化→调整→重构） | **弱对齐** | **遗漏**：lab 的 dynamics 描述的是领域本身的演化模式（如"客户信任度前低后高"），而非图式自身的生命周期阶段。两者概念相近但不同。 |
| `mappings` | 无直接对应 | — | **设计决策**：lab 将 intent→action 映射独立为一个字段，理论不区分图式内容和行动指导 |
| `biases` | 顽固性（难以改变） + 主动选择 | 对齐 | **设计决策**：lab 将"错误信念→事实纠正"结构化为独立字段，是理论概念的工程化表达 |

## 理论有而 Lab 无

| 理论概念 | 说明 | 是否应补 |
|---------|------|---------|
| 图式生命周期阶段标记 | 理论区分形成/强化/调整/重构四个阶段，lab schema 无此标记 | 推荐。标记 schema 成熟度有助于使用者判断可信度 |
| 子图式层级 | 理论说图式按层次组织（主图式含子图式），lab 的 schema 是扁平的 | 推荐。复杂 schema（如技术升级）天然含有子结构 |
| 同化/顺应的显式区分 | 理论的核心机制，lab 在因果链中有保留类/需验证类区分，但未与理论显式关联 | 建议。保留类=同化，需验证类=顺应，应文档化此对应关系 |
| 默认值的"缺失时填充"语义 | 理论强调"信息缺失时图式提供默认值"，lab 的 properties 只表达了"有什么属性"而非"缺什么时用什么" | 低优先。工程上 key-value 已够用，语义增强可延后 |

## Lab 有而理论无

| Lab 字段 | 说明 | 判定 |
|---------|------|------|
| `usage` | 显式适用场景 | 合理的工程扩展 |
| `boundaries` | 显式边界条件 | 合理的工程扩展 |
| `mappings` | 意图→行动的转换规则 | 合理的工程扩展 |
| `biases` + `causals` | 结构化的反例知识和因果链 | 合理的工程扩展（理论描述现象，lab 工程化） |
| `dynamics` | 领域演化模式（非图式自身演化） | 合理的工程扩展，但字段名易混淆 |

## 关键发现

**最大的偏差是 `dynamics` 字段的命名歧义。**

理论中的 dynamics = 图式自身的生命周期演化（形成→强化→调整→重构）。
Lab 中的 dynamics = 领域/场景的演化特征（如"客户信任度前低后高"）。

这是同一个词指向两个不同概念。建议：
- 保留 lab 的 dynamics 字段（领域演化），因为它对咨询场景有用
- 在 schema 元信息中补充一个 `maturity` 字段标记图式自身的生命周期阶段（forming/reinforcing/adjusting/restructuring）

**保留类/需验证类应显式关联同化/顺应。**

这是最值得做的理论引用——它解释了"为什么有些因果链需要验证"的理论依据，而不是一个拍脑袋的设计。

## 结论

Lab 的 schema 定义不是"错误的"，而是**无理论意识地重新发明了图式理论的工程等价物**。8 个字段中：
- 3 个有理论对应但形式不同（entities、causals、properties）
- 1 个字段名和理论概念冲突（dynamics）
- 1 个与理论对齐（biases）
- 3 个是合理的工程扩展（usage、boundaries、mappings）

没有严重错误，但 dynamics 的命名歧义和子图式层级的缺失是值得修补的缺口。
